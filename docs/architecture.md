# Архитектура версии 0.2.0

React/TypeScript/Vite → Nginx → FastAPI/Pydantic → SQLAlchemy 2/psycopg 3 → PostgreSQL 17. Три сервиса Compose: mobile-app, api-be, postgres. Браузер не подключается к БД. Админка — раздел того же frontend.

## Границы модулей
- src/app/ApiApp.tsx: маршруты, формы, состояния загрузки и ошибок, прежний визуальный стиль.
- src/data/api.ts и src/domain/api-models.ts: типизированные асинхронные репозитории HTTP.
- backend/app/main.py: синхронные def-обработчики, проверки владельца/ролей, транзакционные сценарии.
- backend/app/security.py: Argon2id, cookie-сессии, CSRF, PostgreSQL-лимиты попыток.
- backend/app/models.py, schemas.py, outputs.py: ORM, входная валидация и публичные модели без секретов.
- backend/app/assessment.py: заменяемый расчёт answers-1.0.0.
- backend/app/content.py, seed.py: оригинальный набор v1 и повторяемый seed.
- backend/migrations: неизменяемые Alembic-ревизии.

## Схема данных
| Таблица | Связь и ограничения |
| --- | --- |
| users | email уникален, role parent/admin, только хеш пароля |
| auth_sessions | FK user, уникальный хеш случайного токена, срок действия |
| login_buckets | окно и счётчик для хеша IP/email, блокировка строки |
| children | FK owner, возраст/пол/интересы/город, время и версия согласия |
| task_sets | уникальны code/version; JSON заданий и серверных ключей |
| test_sessions | FK child и task_set, снимок профиля, версия алгоритма, шаг/фаза/статус |
| answers | FK session, уникальна пара session/task |
| results | один сохранённый результат на session, версия алгоритма и JSON показателей |
| clubs | возрастные ограничения, город, адрес/телефон/цена/URL, архив |
| recommendation_rules | один набор правил на club, показатель/порог/приоритет/объяснение |
| feedback | FK user, рейтинг 1–5, текст, уникальна пара user/request |
| events | FK user/session/club, kind, уникальна пара user/request |

UUID идентифицируют сущности. Старт блокирует строку ребёнка: параллельные старты возвращают одно незавершённое прохождение. request_id старта является устойчивым id сессии, повтор после завершения возвращает прежнюю сессию. Ответ и позиция изменяются одной транзакцией с блокировкой прохождения. Точный повтор ответа безопасен; другой ответ на сохранённый шаг возвращает 409. Результат, завершение и событие completed сохраняются атомарно. Повтор завершения возвращает прежний результат.

Стадия памяти view/answer хранится на сервере. До скрытия выдаётся материал без вариантов; после скрытия материал не выдаётся. Ключ correct не присутствует в публичной TaskOut. Нельзя защитить запоминание от инструментов разработчика или скриншотов: это ознакомительный сценарий, не прокторинг.

## Версии
Набор attention-memory-7-9/1.0.0 содержит ровно 12 заданий. Новая редакция создаётся новым TaskSet, без обновления старого JSON. Исторические результаты не пересчитываются при открытии. При введении нового алгоритма необходимо сохранить реализацию старой версии для ранее начатых сессий.

Правила рекомендаций предварительные: возраст и нормализованный город из снимка сессии, затем диапазон процента выбранного параметра, приоритет по убыванию и UUID по возрастанию. Верхняя граница — пять программ. Если совпадений меньше, показывается фактическое число. metric=any не ограничивает показатель; иные правила проверяют minimum ≤ percent ≤ maximum. Начальные специальные правила: attention/memory от 0 до 67%, приоритет 10; общие — any, приоритет 0. Это не валидированная методика.

Основные данные не зависят от IndexedDB. Старый адаптер и его тесты оставлены как предыдущая итерация, активное приложение их не импортирует. Автоматической миграции или удаления браузерных данных нет.
