# Резервные копии

Команды из корня проекта, PowerShell, при запущенных контейнерах:

```powershell
./tools/backup.ps1
```

Копируются PostgreSQL в custom-формате и весь постоянный том /data (фотографии, приватные документы, аудио и модели). В каталоге backups создаются database.dump, files.tar.gz и SHA-256. Эти данные не входят в Git: резервная копия содержит персональные сведения и требует отдельного защищённого хранения. Перед резервированием файлов на рабочем сервере следует приостановить изменяющие запросы: согласованный снимок БД и файлов в условиях конкурентных загрузок этим локальным скриптом не гарантируется.

Для исходной версии без файлового тома допустим `./tools/backup.ps1 -DatabaseOnly`. Это не полная копия новой версии.

Проверка восстановления выполняется только на изолированном окружении:

```powershell
./tools/backup.ps1 -Project liga-mvp-tests -Database liga_test
./tools/restore-test.ps1 -BackupDirectory ./backups/<каталог-тестовой-копии>
```

restore-test проверяет имя liga_test и SHA-256, останавливает только тестовые API/frontend, восстанавливает тестовую БД и файловый том, запускает их обратно. Параметров для восстановления рабочей БД в нём нет. Скрипт не очищает каталог /data перед распаковкой, поэтому для точного восстановления файлов в иной момент нужен отдельный пустой тестовый том; проверка существовавших файлов не подтверждает удаление всех более новых файлов.

Восстановление рабочей базы — отдельная административная операция с остановкой записи, проверенным архивом и планом отката. Автоматический down -v не используется.
