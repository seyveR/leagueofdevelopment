# Проверка с iPhone в домашней сети

ПК и iPhone должны быть подключены к одному роутеру: ПК может использовать Ethernet, телефон — Wi-Fi. Гостевая сеть с изоляцией устройств может препятствовать соединению.

Локальный запуск с отдельным Compose-файлом, PowerShell:

```powershell
$env:LAN_IP='192.168.0.15' # заменить, если домашний IPv4 компьютера изменился
docker compose -f compose.yaml -f compose.lan.yaml up -d --no-deps --no-build --pull never --wait api-be mobile-app
```

Открыть в Safari http://192.168.0.15:8080. Адрес 127.0.0.1 на телефоне означает сам телефон и не ведёт на ПК. Нужно использовать http, не https. Компьютер и Docker должны оставаться включёнными.

Дополнение публикует интерфейс на loopback и указанном домашнем IP. PUBLIC_ORIGIN содержит оба адреса для корректного сохранения форм. PostgreSQL не публикуется в домашнюю сеть; существующий DBeaver остаётся на loopback 5434. Порты роутера пробрасывать не требуется. Изменений брандмауэра и VPN скрипт не делает.

14 ноября 2026 проверены оба HTTP-адреса с компьютера, слушающие сокеты 127.0.0.1:8080 и 192.168.0.15:8080. Проверка с физического iPhone ещё требует открытия адреса пользователем. Если не открывается: проверить Wi-Fi, отсутствие изоляции клиентов, ограничения VPN на доступ в локальную сеть и правила брандмауэра. Не отключать защиту целиком.

Для записи: Пункт управления iPhone → Запись экрана. Видео сохраняется в Фото. Обычная веб-версия работает через Safari; HTTPS-установка PWA и автономная работа этим запуском не подтверждаются.

Повторный запуск без пересоздания контейнеров: docker compose start. Остановка: docker compose stop. Возврат к доступу только с ПК:

```powershell
docker compose -f compose.yaml up -d --no-deps --force-recreate --no-build --pull never --wait api-be mobile-app
```

Данные при этих командах сохраняются; down -v не используется.
