# Публичная установка

Адрес: https://ligarazvitiya29.ru. `www` перенаправляет на основной домен. HTTPS обслуживает Caddy с автоматическим продлением сертификатов Let's Encrypt.

Развёрнуто на Ubuntu 24.04, 2 CPU / 4 ГБ RAM. Сервер: `212.109.218.51`. Каталог установки: `/opt/league`, проект Docker Compose: `liga-public`. Образы приложения закреплены за коммитом `8705a79`; исходники этой версии находятся в `/opt/league/source`.

Перенесены полная база PostgreSQL, загруженные файлы и озвучка. Прежние аккаунты и пароли сохранены. Новые пользователи регистрируются через интерфейс. Локальная и серверная базы теперь независимы. Для командного тестирования используйте публичный адрес.

## Обслуживание

Следующие команды выполняются по SSH на сервере:

```sh
cd /opt/league
docker compose ps
docker compose logs --tail=100 api-be
```

Остановка и повторный запуск с сохранением данных:

```sh
cd /opt/league
docker compose stop
docker compose up -d --no-build --pull never --wait
```

Контейнеры автоматически запускаются после перезагрузки сервера, если перед этим не были остановлены вручную. Caddy и Docker включены как системные службы. Закрытие SSH и выключение компьютера разработчика не останавливают сайт.

Не выполняйте `docker compose down -v`: это удалит том базы. База не опубликована в интернет; приложение слушает только `127.0.0.1:8080`, Caddy принимает HTTP/HTTPS. Межсетевой экран разрешает SSH, HTTP и HTTPS.

Секреты находятся только на сервере в `/opt/league/.env` с правами `600`. Не добавляйте этот файл, дампы, SSH-ключи или пользовательские файлы в Git. В репозитории находятся конфигурация и скрипты из `deploy/`, без паролей.

## Резервные копии

Таймер `league-backup.timer` ежедневно около **03:15 по Москве** запускает `/opt/league/backup.sh`. На время согласованного копирования приложение кратко останавливается, затем запускается снова. База остаётся запущенной. Каталог каждой копии: `/opt/league/backups/<время UTC>/`; внутри `database.dump`, `files.tar.gz`, `SHA256SUMS`.

Ручной запуск и проверка:

```sh
systemctl start league-backup.service
systemctl show league-backup.service -p Result -p ExecMainStatus
systemctl list-timers league-backup.timer
```

Проверка целостности конкретной копии:

```sh
cd /opt/league/backups/<время UTC>
sha256sum -c SHA256SUMS
```

Копии на том же VPS не защищают от потери сервера. Автоматическое внешнее хранилище пока не подключено; регулярно скачивайте полный каталог копии на другой компьютер. Удаление старых копий выполняется вручную с контролем свободного места (`df -h`). Исходная копия переноса также сохранена на компьютере разработчика вне Git.

`restore-initial.py` предназначен только для первичного импорта: он отказывается перезаписывать заполненную базу. Для аварийного восстановления сначала подготовьте отдельную пустую базу и отдельный том файлов, проверьте контрольные суммы, восстановите дамп через `pg_restore` и файлы из архива; переключайте рабочую установку после проверки. Не используйте первичный импорт для обновления приложения.

## Проверка развёртывания

Проверены HTTPS обоих доменов и перенаправление `www`, API health, Secure/HttpOnly cookie, регистрация родителя, создание ребёнка, все 20 заданий младшей группы, продолжение после перезагрузки, результат, рекомендации, запись и контакты в заявке. Технический аккаунт проверки удалён через удаление собственного аккаунта. Существующие данные не удалялись.

Сверены количества и контрольные суммы строк всех 32 таблиц: после проверки отличаются только технические счётчики входа. Контрольные суммы содержимого файлов совпали. Первая серверная резервная копия завершилась успешно, приложение после остановки и запуска восстановило работу.

Браузерная проверка выполнена в Edge при размере экрана 430×932, а не на физическом iPhone. На компьютере проверки DNS ещё содержал старый адрес парковки: браузер был направлен на новый сервер через локальное правило разрешения имени, с обычной проверкой TLS. Если после изменения DNS открывается парковка регистратора, дождитесь обновления кеша или проверьте домен через другую сеть. Для iPhone открывайте HTTPS-домен; старый ярлык с локальным IP нужно заменить.

## Следующее обновление

Перед обновлением создайте резервную копию. Соберите образы новой версии, перенесите их на VPS, загрузите через `docker load`, измените `APP_VERSION` в серверном `.env` и выполните `docker compose up -d --no-build --pull never --wait`. API при старте выполняет миграции Alembic; изучайте их до обновления. Откат только образов не отменяет миграции базы. Не переносите локальную базу поверх рабочей: новые заявки и регистрации существуют уже на сервере.
