# Отчёт проверки версии 0.2.0

Проверено 22 октября 2026 года. Docker Desktop 4.44.2, Engine 28.3.2, Compose 2.39.1. Основной проект liga-mvp: mobile-app, api-be, postgres. Изолированный проект liga-mvp-tests: те же три сервиса, база liga_test, отдельный том, порт 8081. Пользовательская база liga не очищалась.

## Выполненные команды и результаты

- npm run build: проверка TypeScript и production-сборка успешны. Сборка также выполнена внутри Node-стадии Docker.
- npm test: 14 успешных тестов. Из них 3 новых проверки границы API (CSRF/cookie, сетевая ошибка, статус запрета), 11 сохранённых проверок предыдущего локального адаптера. Старые проверки не считаются доказательством работы нового сервера.
- pytest -q внутри тестового API с реальным PostgreSQL: 12 успешных тестов.
- npm run test:e2e: 3 успешных сквозных сценария Edge headless, через production Nginx и отдельную тестовую БД.
- npm audit после обновления Vitest до 4.1.12: 0 известных уязвимостей в npm-дереве. Общий аудит безопасности Python/ОС этим не подтверждается.
- docker compose up -d --wait: основной API и PostgreSQL готовы, Nginx работает.
- GET /, /profile, /admin, /feedback, /api/health, /api/docs и /api/openapi.json на 127.0.0.1:8080: HTTP 200. Защищённые экраны дополнительно проверены в браузере; получение HTML само по себе не является проверкой авторизации.

## Исправление сессий и смена пароля — 0.2.1, 22 октября 2026

TypeScript и production-сборка внутри Docker успешны; оба образа пересобраны. Клиентские тесты: 18/18 (7 проверок API и 11 сохранённых проверок локального адаптера). Серверные тесты с PostgreSQL в liga_test: 17/17. Сквозные сценарии Edge headless через тестовый Nginx на 8081: 6/6. Сохранилось предупреждение deprecation Starlette/AnyIO.

Проверены смена собственного пароля для parent/admin, неверный текущий пароль без выхода, несовпадение подтверждения, короткий пароль, CSRF, запрет чужого email в запросе, отзыв всех собственных сессий с сохранением чужих, откат хеша и отзыва сессий при ошибке commit. Выход после внешнего отзыва сессии и его повтор успешны. Клиентские проверки включают новый CSRF после смены пароля и защиту нового входа от запоздалого 401 прежней сессии.

В браузере для обеих ролей проверены форма из профиля/админки, ошибки ввода, возврат на вход с сообщением об успехе, отказ старого пароля, вход с новым, перезагрузка и выход. Во втором независимом браузерном контексте защищённое действие после смены пароля возвращает на вход. Дополнительно проверены выход из открытой вкладки с уже отозванной сессией и проверка при событии возврата фокуса. Повторно прошли три прежних основных сценария. Реальный телефон не использовался.

Рабочие API и frontend обновлены до 0.2.1 без пересоздания PostgreSQL и без изменения паролей пользовательских записей. Основная база не использовалась для тестов.

## Серверные проверки

Подробная статистика администратора: 22/22 серверных тестов, 18/18 клиентских, TypeScript и production-сборка Docker успешны. Проверены список завершённых прохождений двух родителей, историческое имя ребёнка после редактирования профиля, сохранённый результат, все 12 ответов, отсутствие паролей/токенов в ответах, 404 незавершённого/несуществующего прохождения, 401/403 на все новые API, границы и разбиение страниц. Статистика кружков проверена на пустом состоянии, повторе request_id без дублей, новых открытиях, отсутствии учёта обычного каталога и сохранении истории архивного кружка.

В браузере успешно выполнены 9 сценариев. Административный расширен переходами из обеих карточек, раскрытием ответа, возвратом к списку, reload подробного маршрута, данными о единственном переходе и активной вкладкой статистики. Ширины подробного отчёта: 360/390/430/1280 без горизонтальной прокрутки. Первоначальная ошибка проверки была в неоднозначном селекторе из 12 одинаковых подписей; селектор ограничен раскрытым заданием, административный сценарий повторно успешен. Просмотрены снимки admin-completion-430.png и admin-transitions-430.png. Физический телефон не проверялся. Новая схема БД и сброс рабочих данных не требуются.

Исправление ограничения входа: 20/20 серверных тестов, 18/18 клиентских, 9/9 браузерных; TypeScript успешен, API-образ пересобран. Проверены 32 последовательных правильных входа с чередованием parent/admin при заполненных старых IP/email-счётчиках; отсутствие блокировки; 14 ошибок и порог 15; Retry-After 60, затем 20 без продления паузы; истечение паузы с управляемыми часами без ожидания минуты; успешный вход во время паузы, сброс последовательности и независимость email. В браузере пройдены 15 неверных вводов через форму с последующим немедленным успешным входом. Тесты выполнялись только в liga_test. Рабочий API обновлён без сброса пользовательской базы или смены паролей; старые лимиты входа больше не применяются. Ограничения регистрации и смены пароля оставлены отдельно.

Мобильная компоновка обновлена после проверки 0.2.1: SVG-иконки и подписи, четыре раздела для каждой роли, единая навигация вместо дублирования административных ссылок. Добавлены два браузерных сценария с мобильным контекстом 430×932, touch и deviceScaleFactor=3 (размер iPhone 14 Pro Max, браузер Edge/Chromium). На четырёх маршрутах каждой роли проверены ширины 360/390/430/768/1280, отсутствие горизонтального выхода, единственный активный пункт, зоны нажатия от 44 px, компактная высота панели и доступность footer после прокрутки. Заголовок администрирования помещается в одну строку на проверенных мобильных ширинах. Просмотрены снимки test-results/mobile-parent-430.png и mobile-admin-430.png. Это эмуляция, физический iPhone и Safari не проверялись.

## Браузерные проверки

Полный родительский путь: регистрация → согласие/профиль → инструкция → 12 заданий → результат → 3–5 рекомендаций → адрес/телефон → оценка приложения/предложение → выход. Перезагрузка проверена после регистрации, на обычном шаге, после скрытия материала памяти и на результате.

Отдельно проверены два ребёнка, сохранение ответа с сетевой ошибкой и повтором, неактивная кнопка без выбора, возраст 6 лет, пустой город каталога, отказ родителю на /admin. Администратор входит, смотрит статистику, добавляет кружок и правило, редактирует/архивирует, видит обратную связь.

Проверены ширины 360/390/430/1280 px на главной, профиле, каталоге, обратной связи и форме ребёнка, без горизонтальной прокрутки. Просмотрен снимок test-results/mvp-home-390.png. Реальный телефон не использовался.

## Перезапуск и сохранность

В liga-mvp-tests выполнен restart всех трёх контейнеров и ожидание готовности. До/после совпали количества users=5, children=4, test_sessions=2, answers=13, results=1, feedback=1, events=2, auth_sessions=5 и контрольная сумма идентификаторов/значений ответов. С той же cookie после перезапуска /api/auth/session вернул прежнего администратора. Это фактическая проверка тестового окружения на той же схеме и постоянном томе, не удаление/пересоздание пользовательских данных.

Во время первоначального скачивания образов Docker Hub был TLS handshake timeout. Повторное скачивание и сборка прошли. В серверных тестах остаётся одно предупреждение deprecation библиотеки Starlette TestClient/AnyIO; тесты успешны. Отдельный compileall без каталога кэша не выполнился из-за запрета записи __pycache__ непривилегированному пользователю; это не считается успешной проверкой. Импорт и выполнение модулей подтверждены фактическими тестами и запуском API.

## Не проверено

Физический телефон, Safari/iOS/Android-версии, качество доступных русских голосов speechSynthesis, экранный диктор, предельная нагрузка, 99% доступности, HTTPS и размещение в РФ. Полная внешняя экспертиза безопасности, правовая готовность согласия и методическая валидизация также не заявляются.

Основное приложение оставлено работающим по 127.0.0.1:8080; тестовый проект после проверки остановлен без удаления тома.
