# Лига развития Версия 0.2.1

Минимальный мобильный веб-прототип по ТЗ №1 из TZ.docx и уточняющему заданию от 22 октября 2026 года. ТЗ №2 не реализуется. Новые требования заменяют прежнюю локальную версию.

Родитель: регистрация → профиль ребёнка → 12 заданий → фактический результат → рекомендации → контакты кружка → обратная связь.
Администратор: кружки, правила рекомендаций, статистика с переходом к прохождениям и ответам, переходы к кружкам, обратная связь. Интерфейс русский, нейтральные подписи, прежние светлый фон и цветная геометрия.

## Запуск только с Docker Desktop

Репозиторий: https://github.com/seyveR/leagueofdevelopment. Текущая версия сохранена в `main`, дальнейшая разработка ведётся в `test`. Направление следующих итераций — [заявки, кабинет организации, запись и календарь](docs/roadmap.md); эти функции пока не реализованы.

На компьютере нужны Docker Desktop с Linux-контейнерами и браузер. Python, Node.js и PostgreSQL на компьютере для запуска не нужны.

В папке D:\NARFU\aks уже подготовлен локальный .env со случайным паролем БД; он исключён из Git и образа frontend. Для новой копии проекта скопируйте .env.example в .env и замените POSTGRES_PASSWORD собственным длинным случайным паролем. Не перезаписывайте существующий .env: смена переменной не меняет пароль уже созданной БД.

В терминале из папки проекта:
```powershell
docker compose up --build -d
docker compose ps
docker compose logs --tail 100 api-be
```

Адреса:
- Приложение: http://127.0.0.1:8080/
- Админка: http://127.0.0.1:8080/admin
- Документация API: http://127.0.0.1:8080/api/docs
- OpenAPI: http://127.0.0.1:8080/api/openapi.json
- Проверка API/БД: http://127.0.0.1:8080/api/health

Для запуска API сначала ожидается PostgreSQL, затем выполняются Alembic и повторяемое заполнение справочников. Nginx раздаёт сборку и проксирует /api. Прямое открытие и обновление /profile, /admin и других маршрутов поддерживается. API и PostgreSQL не публикуют порты на компьютере. Приложение привязано к 127.0.0.1, поэтому с телефона сейчас недоступно.

Остановка и повторный запуск:
```powershell
docker compose stop
docker compose start
docker compose logs -f --tail 100 api-be mobile-app
```
Ctrl+C при просмотре логов останавливает только просмотр. Именованный том liga-mvp_liga-data хранит БД. Остановка, рестарт, пересоздание контейнеров и обычный docker compose down не удаляют его. Не выполняйте down -v или volume rm для сохранения данных.

## Администратор

Роль администратора нельзя выбрать при регистрации. Пароля по умолчанию нет. Создание отдельной локальной записи:
```powershell
docker compose exec api-be python -m app.cli create-admin --email admin@example.com
```
Команда дважды запросит пароль без отображения ввода (10–128 символов). Затем войдите через обычную форму: роль откроет /admin. Команда не повышает роль существующего родителя и не перезаписывает занятый email. Пароль не передаётся аргументом команды и не записывается в исходники.

Восстановления забытого пароля через email пока нет.

| Переменная | Назначение |
| --- | --- |
| POSTGRES_PASSWORD | Пароль пользователя liga в PostgreSQL; только серверный контейнер |
| APP_PORT | Локальный порт Nginx, по умолчанию 8080 |
| PUBLIC_ORIGIN | Разрешённый Origin изменяющих запросов, по умолчанию http://127.0.0.1:8080 |
| COOKIE_SECURE | false для локального HTTP; true при будущем HTTPS |

## Хранение и API

Основные данные теперь в PostgreSQL. Frontend обращается к асинхронным репозиториям src/data/api.ts; компоненты не вызывают Dexie или SQL. Старые файлы локального адаптера сохранены как исходная итерация и не входят в активный путь приложения. Старый IndexedDB не читается, не переносится и не удаляется. Созданные раньше локальные профили не появятся в новых учётных записях автоматически.

Пароли хешируются Argon2id. Серверные сессии живут 7 дней; случайный токен хранится в HttpOnly/SameSite=Strict cookie, в БД — его SHA-256. CSRF: отдельная HttpOnly-cookie, токен в ответе /auth/session и заголовке X-CSRF-Token, проверка Origin и Sec-Fetch-Site. Новая авторизация меняет cookie; выход отзывает текущую сессию в БД. Успешные входы не ограничиваются по частоте. Для каждого email PostgreSQL считает последовательные неверные входы: после 15 ошибок — пауза 60 секунд; попытки в течение паузы не продлевают её. Правильный пароль позволяет войти даже во время паузы и сбрасывает счётчик. После окончания паузы начинается новый отсчёт. Счётчики других аккаунтов и прежние общие IP-ограничения на вход не влияют. Регистрация и смена пароля сохраняют отдельные прежние ограничения (5 на email/учётную запись и общий для этих операций IP-лимит 30 за 15 минут).

Все обращения к детям, ответам, прохождениям и результатам проверяют владельца на сервере. Родитель не имеет доступа к административным маршрутам. Синхронный SQLAlchemy используется в def-обработчиках и зависимостях FastAPI; async-middleware работает только с заголовками.

Подробнее: [архитектура](docs/architecture.md), [API](docs/api.md), [происхождение контента](docs/content.md), [проверки](docs/verification.md).

## PostgreSQL и миграции

Консоль внутри контейнера, пароль на хосте не нужен:
```powershell
docker compose exec postgres psql -U liga -d liga
```
Примеры безопасных запросов:
```sql
SELECT role, count(*) FROM users GROUP BY role;
SELECT count(*) FROM children;
SELECT status, count(*) FROM test_sessions GROUP BY status;
SELECT algorithm_version, scores FROM results LIMIT 5;
SELECT kind, count(*) FROM events GROUP BY kind;
SELECT version FROM task_sets;
```
Не выгружайте поля password_hash, token_hash и персональные данные в публичные логи. Закончить psql: \q.

Опциональный доступ с компьютера:
```powershell
docker compose -f compose.yaml -f compose.db-access.yaml up -d
```
Подключение: 127.0.0.1:5434, база liga, пользователь liga, пароль из .env. Порт привязан только к loopback. Обычно он не нужен. Чтобы убрать публикацию, снова выполните docker compose up -d с основным файлом. БД останется в томе.

Миграция backend/migrations/versions/0001_initial.py создаёт таблицы, внешние ключи, индексы и ограничения. Выполненные ревизии не редактировать; изменения схемы оформлять новой миграцией. Начальные данные backend/app/seed.py запускаются повторно без дублей и без перезаписи отредактированных кружков. Содержимое начатых прохождений берётся из сохранённой версии набора. Новое содержание требует нового TaskSet с новой версией; старые наборы не удалять.

## Проверки для разработчика

Обычному пользователю эти инструменты не нужны. Для frontend-тестов на хосте нужны Node.js 20.15+ и npm; Windows-тесты используют установленный Edge.

```powershell
npm ci --legacy-peer-deps
npm run typecheck
npm test
npm run build
```

Интеграционные тесты используют отдельный Compose-проект и базу liga_test:
```powershell
docker compose -p liga-mvp-tests -f compose.yaml -f compose.test.yaml up --build -d --wait
docker compose -p liga-mvp-tests -f compose.yaml -f compose.test.yaml exec -T api-be pytest -q
```
Фикстуры очищают ТОЛЬКО БД с суффиксом _test, до начала тестов проверяют её имя и применяют миграции. Не направляйте тесты на пользовательскую базу. Данные основного проекта не очищаются.

Для браузерного сценария создайте администратора ТОЛЬКО в тестовой базе. В одном PowerShell-сеансе:
```powershell
$env:BROWSER_ADMIN_PASSWORD = [Guid]::NewGuid().ToString('N') + [Guid]::NewGuid().ToString('N')
docker compose -p liga-mvp-tests -f compose.yaml -f compose.test.yaml exec -T -e BROWSER_ADMIN_PASSWORD api-be python -m tests.prepare_browser
npm run test:e2e
```
Тестовые админ-записи browser-admin@example.com и password-admin@example.com. Команда подготовки не создаёт администратора в базе liga. Сценарий смены пароля меняет пароль второй тестовой записи, поэтому перед полным повтором запустите pytest (он очистит только liga_test), затем подготовку администраторов. Браузерный тест использует порт 8081, собственные новые учётные записи и изолированные браузерные контексты. Старые тесты первой локальной итерации не запускаются как новые сквозные проверки.

Закончить тестовое окружение без удаления тома:
```powershell
docker compose -p liga-mvp-tests -f compose.yaml -f compose.test.yaml stop
```
